# EAPU: SATD Comment Classification via Expert / Anti-Expert Parameter Unlearning

This directory (`EAPU/`) contains the experiments for Self-Admitted Technical Debt(SATD) binary classification of code comments.

The core idea is to train two LoRA adapters on top of the same base model:

- Expert: a classification adapter trained on the normal LOPO training set;
- Anti (anti-expert): an adapter trained on the Expert's misclassified samples
  (false positives / false negatives) with their labels flipped, which captures the
  "directions in which the expert tends to make mistakes".

At inference time the Anti adapter is never loaded directly. Instead, its parameter delta
relative to the base model is top-k sparsified in the last N layers, and subtracted
from the Expert parameters with coefficient λ:

```
W_final = W_expert − λ · TopK( W_anti − W_base , ratio = topk )
```

- Only `q_proj / v_proj` in the last `last_n_layers` transformer layers (plus the
  classification head `score.weight`) are modified; all other layers stay identical to Expert.
- A grid search over `λ × topk × last_n_layers` finds the configuration with the best
  average F1 across the 10 LOPO projects.

### Raw CSV format

`dataset/satd-dataset-code_comments*.csv` have three columns:

| column | meaning |
|---|---|
| `project` | one of the 10 Java projects |
| `text` | the code comment |
| `classification` | fine-grained label (see below) |

Fine-grained labels and their binary SATD mapping:

| classification | rows (raw / dedup) | binary `answer` |
|---|---|---|
| `non_debt` | 58,204 / 35,522 | **0** (non-SATD) |
| `code/design_debt` | 2,703 / 2,262 | **1** (SATD) |
| `requirement_debt` | 757 / 550 | **1** |
| `defect_debt` | 472 / 351 | **1** |
| `test_debt` | 85 / 81 | **1** |
| `documentation_debt` | 54 / 49 | **1** |

### Experiment JSONL format

One JSON object per line (used by all training/scoring scripts):

```json
{"project": "argouml", "instruction": "Determine whether the comment contains SATD.", "input": "// TODO: fix this later", "answer": 1}
```

- `input`: the code comment text; `answer`: binary label, `1` = SATD, `0` = non-SATD.
- Scored files additionally contain `_pred / _prob_0 / _prob_1 / _margin_to_boundary`.
- Anti data additionally contains `_source` (`fp` or `fn`).

## 3. Full Pipeline

> All commands below assume you are inside the `project/` directory:
>
> ```bash
> cd EAPU/project
> ```
>
> Let `<TAG>` denote the experiment tag (e.g. `oldbase` / `llama2` / `deepseek`, one per
> base model). The 10 project names are listed in Section 7.
> The examples below use project `apache-ant-1.7.0` and tag `demo`.

### Step 0: Build the LOPO splits

[data_sync_lopo.py](project/data_sync_lopo.py) performs the Leave-One-Project-Out split.
It reads two source files and writes two LOPO trees:

- input:  `../data/satd_dataset.jsonl`     (SATD samples, `answer=1`)
- input:  `../data/negative_samples.jsonl` (non-SATD samples, `answer=0`)
- output: `../data/expert_lopo/split_<project>/{train,val,test}.jsonl`
- output: `../data/anti_lopo/split_<project>/{train,val,test}.jsonl`

```bash
# from EAPU/project
python data_sync_lopo.py
```

For every project it:

1. puts all samples of that project into `test` (the held-out project);
2. splits the remaining projects' samples **9:1** into `train` / `val`
   (`train_test_split(..., test_size=0.1, random_state=42)`);
3. repeats independently for the SATD source (`expert_lopo/`) and the negative source
   (`anti_lopo/`).

> The two input jsonl files are **not** shipped. Produce them from the raw CSVs in
> `dataset/` (apply the binary mapping from the table in Section 1, e.g. with the
> de-duplicated CSV) and place them at `EAPU/data/satd_dataset.jsonl` and
> `EAPU/data/negative_samples.jsonl` before running this step. The input files must use the
> experiment JSONL format (`project` / `input` / `answer` fields).

### Step 1: Train the Expert classifier (LoRA)

```bash
python train_expert_classifier.py \
  /path/to/base-model \
  ../data/expert_lopo/split_apache-ant-1.7.0 \
  ckpt/expert_demo_apache-ant-1.7.0
```

- Arguments: `<base_model_path> <data_dir> <output_dir>`
- LoRA: `r=16, alpha=32, target_modules=[q_proj,v_proj], dropout=0.05`; the classification
  head `score` is fully trained (`modules_to_save=["score"]`).
- 3 epochs, lr=1e-4, batch size 4, fp16, best checkpoint selected by validation F1.
- Artifact: `ckpt/expert_demo_apache-ant-1.7.0/expert_adapter_final/`

### Step 2: Score the training set with the Expert

```bash
python score_with_expert.py \
  --input_path      ../data/expert_lopo/split_apache-ant-1.7.0/train.jsonl \
  --base_model_path /path/to/base-model \
  --expert_adapter_path ckpt/expert_demo_apache-ant-1.7.0/expert_adapter_final \
  --output_path     ckpt/runs/anti_demo_apache-ant-1.7.0/train_scored.jsonl \
  --batch_size 1 --max_length 512
```

Every output line gets a `_pred` (predicted label) and both class probabilities, which are
used in the next step to identify FP/FN.

### Step 3: Build the label-flipped Anti dataset

```bash
python build_anti_dataset_flip.py \
  --input_path ckpt/runs/anti_demo_apache-ant-1.7.0/train_scored.jsonl \
  --output_dir ckpt/runs/anti_demo_apache-ant-1.7.0/anti_data \
  --use_fp --use_fn \
  --dev_ratio 0.1 --seed 42
```

- `--use_fp`: take **false positives** (answer=0, pred=1) and flip their labels to 1;
- `--use_fn`: take **false negatives** (answer=1, pred=0) and flip their labels to 0;
- at least one of the two flags must be provided.
- Outputs: `train.jsonl / dev.jsonl / preview.jsonl / meta.json`.

### Step 4: Train the Anti LoRA from the base model

```bash
python train_anti_from_base_lora.py \
  --base_model_path /path/to/base-model \
  --tokenizer_path  /path/to/base-model \
  --data_dir        ckpt/runs/anti_demo_apache-ant-1.7.0/anti_data \
  --output_dir      ckpt/runs/anti_demo_apache-ant-1.7.0 \
  --fp16
```

- Note: the Anti adapter trains **LoRA parameters only** (`modules_to_save=None`, the
  classification head is frozen), which distinguishes it from the Expert (whose head is
  trainable).
- Defaults: 5 epochs, lr=5e-5, `r=16/alpha=32`, best checkpoint selected by dev F1.
- Artifact: `ckpt/runs/anti_demo_apache-ant-1.7.0/anti_from_base_adapter_final/`

> Steps 1–4 must be run **once per project** (or once on the pooled `dataset/cross_project/`
> data for a global version). Name the outputs `expert_<TAG>_<project>` and
> `runs/anti_<TAG>_<project>` — these exact patterns are required by the orchestrator in
> Step 5.

### Step 5 + 6: Sparse merge and evaluate (single configuration, manual)

```bash
# 5) Merge: produces a full model directory (not an adapter)
python merge_topk_last_layer.py \
  --base_model     /path/to/base-model \
  --expert_adapter ckpt/expert_demo_apache-ant-1.7.0/expert_adapter_final \
  --anti_adapter   ckpt/runs/anti_demo_apache-ant-1.7.0/anti_from_base_adapter_final \
  --output_dir     /tmp/merged_ant_k01_layer4 \
  --lambda_value   0.1 \
  --topk_ratio     0.1 \
  --last_n_layers  4 \
  --dtype float16

# 6) Evaluate on the held-out project test set
python test_classifier_fullmodel.py \
  ../data/expert_lopo/split_apache-ant-1.7.0 \
  /tmp/merged_ant_k01_layer4 \
  test
```

- `test_classifier_fullmodel.py <data_dir> <model_path> <split>`; the split is usually
  `test` (but `val` also works).
- Prints Accuracy / Precision / Recall / F1 / TN-FP-FN-TP to stdout.
- Also appends/writes in the **current working directory**:
  - `results_fullmodel.csv` (one row per evaluation, append mode)
  - `tmp_metric.json` (latest metrics, consumed by the orchestrator)

### Helper: evaluate base + a single adapter (without merging)

```bash
python test_classifier.py \
  ../data/expert_lopo/split_apache-ant-1.7.0 \
  /path/to/base-model \
  ckpt/expert_demo_apache-ant-1.7.0/expert_adapter_final \
  test
```

Results are appended to `results_adapter.csv` in the current directory; a full
classification report and the confusion matrix are also printed.

## 4. One-Command Grid Search (recommended entry point)

Once the Expert / Anti adapters for all 10 projects are ready, run the orchestrator:

```bash
cd EAPU/project
python run_guid_topk_lastlayer.py /path/to/base-model demo
```

Usage: `python run_guid_topk_lastlayer.py <base_model_path> <tag>`

It runs a grid of **6 × 5 × 4 = 120 configurations** (λ × topk × layer), and for each
configuration evaluates all 10 projects via "merge → test → read metrics → delete the
temporary merged model" — 1,200 evaluations in total.

| Hyperparameter | Values |
|---|---|
| `lambda_value` | 0.01, 0.05, 0.1, 0.25, 0.5, 0.75 |
| `topk_ratio` | 0.05, 0.1, 0.25, 0.5, 0.75 |
| `last_n_layers` | 2, 4, 8, 16 |

Results are written to `output/guid_topk_lastlayer_<tag>/` (relative to the orchestrator's
configured `OUTPUT_ROOT`):

| File | Contents |
|---|---|
| `all_results.csv` | Per-(project, λ, topk, layer) metrics (acc/precision/recall/f1 + 4 confusion-matrix cells) |
| `average_results.csv` | Metrics averaged over the 10 projects for each (λ, topk, layer) |
| `best_results.csv` | All configurations sorted by `avg_f1` descending |

Adapter path patterns expected by the orchestrator (names must match exactly):

```
<CKPT_ROOT>/expert_<TAG>_<project>/expert_adapter_final
<RUNS_ROOT>/anti_<TAG>_<project>/anti_from_base_adapter_final
```

### ⚠️ Hard-coded paths in the orchestrator

[run_guid_topk_lastlayer.py](project/run_guid_topk_lastlayer.py) hard-codes an absolute
outer root at the top — it currently points **outside** this `EAPU/` folder:

```python
ROOT        = Path("/home/hbuetea/topk-last_layer")
PROJECT_DIR = ROOT / "project"          # scripts are run from here
DATA_ROOT   = ROOT / "data" / "expert_lopo"
CKPT_ROOT   = ROOT / "ckpt"

```

To run everything self-contained inside `EAPU/`, change them to:

```python

PROJECT_DIR = ROOT / "project"
DATA_ROOT   = ROOT / "data" / "expert_lopo"
CKPT_ROOT   = ROOT / "project" / "ckpt"
RUNS_ROOT   = CKPT_ROOT / "runs"
OUTPUT_ROOT = ROOT / "project" / "output"
```

(The manual Step 1–6 commands in Section 3 use paths relative to `EAPU/project/` and are
not affected by this setting.)

## 5. Parameter Reference

| Parameter | Script(s) | Meaning |
|---|---|---|
| `--lambda_value` (λ) | merge / orchestrator | Strength of the anti-delta subtraction; larger = more "anti-expert" |
| `--topk_ratio` (k) | merge / orchestrator | Per layer, keep only the top-k fraction of parameters by absolute value; all other anti deltas are zeroed (sparsification) |
| `--last_n_layers` | merge / orchestrator | Apply the subtraction only in the last N transformer layers; the classification head `score.weight` is always modified; other layers stay Expert |
| `--dtype` | merge | Merge precision, default `float16` (loading/merging happens on CPU, then saved) |
| `--use_fp / --use_fn` | build_anti | Which error samples go into the Anti data; labels are flipped either way |
| `--dev_ratio` | build_anti | Fraction of the Anti data used as the dev split (default 0.1) |
| `--seed` | data_sync / build_anti | Random seed (42 for both) |

The merge formula once more (last N layers only):

```
Δanti      = W_anti − W_base
mask       = TopK( |Δanti| , ratio = topk )
W_final    = W_expert − λ · (Δanti ⊙ mask)
```

## 6. Script Roles at a Glance

| Script | Role | Key inputs → output |
|---|---|---|
| `data_sync_lopo.py` | Data preparation | `data/satd_dataset.jsonl` + `data/negative_samples.jsonl` → `data/{expert,anti}_lopo/split_*/` |
| `train_expert_classifier.py` | Expert training | base + split dir → `expert_adapter_final/` |
| `score_with_expert.py` | Inference on train | train.jsonl + expert adapter → scored jsonl with `_pred/_prob_*` |
| `build_anti_dataset_flip.py` | Error mining | scored jsonl → label-flipped `train/dev.jsonl` |
| `train_anti_from_base_lora.py` | Anti training | base + anti data → `anti_from_base_adapter_final/` |
| `merge_topk_last_layer.py` | Sparse model merge | expert + anti adapters → merged full model dir |
| `test_classifier_fullmodel.py` | Evaluation | data dir + full model → console metrics + `tmp_metric.json` |
| `test_classifier.py` | Adapter-only evaluation | base + one adapter → metrics + `results_adapter.csv` |
| `run_guid_topk_lastlayer.py` | Orchestration | grid over λ×topk×layer × 10 projects → `output/.../*.csv` |

## 8. End-to-End Command List (TL;DR)

```bash
cd EAPU/project

# 0. prepare LOPO splits (first place data/satd_dataset.jsonl & data/negative_samples.jsonl)
python data_sync_lopo.py
```

For every project `<P>`:

```bash
# 1. expert
python train_expert_classifier.py /path/to/base-model \
    ../data/expert_lopo/split_<P> ckpt/expert_demo_<P>

# 2. score train
python score_with_expert.py \
    --input_path ../data/expert_lopo/split_<P>/train.jsonl \
    --base_model_path /path/to/base-model \
    --expert_adapter_path ckpt/expert_demo_<P>/expert_adapter_final \
    --output_path ckpt/runs/anti_demo_<P>/train_scored.jsonl

# 3. anti dataset (flip labels)
python build_anti_dataset_flip.py \
    --input_path ckpt/runs/anti_demo_<P>/train_scored.jsonl \
    --output_dir ckpt/runs/anti_demo_<P>/anti_data \
    --use_fp --use_fn

# 4. anti LoRA from base
python train_anti_from_base_lora.py \
    --base_model_path /path/to/base-model --tokenizer_path /path/to/base-model \
    --data_dir ckpt/runs/anti_demo_<P>/anti_data \
    --output_dir ckpt/runs/anti_demo_<P> --fp16
```

After all 10 projects are done (and after fixing the hard-coded paths in Section 4 if you
run inside `EAPU/`):

```bash
python run_guid_topk_lastlayer.py /path/to/base-model demo
# inspect the ranking
column -s, -t output/guid_topk_lastlayer_demo/best_results.csv | less -S
```
